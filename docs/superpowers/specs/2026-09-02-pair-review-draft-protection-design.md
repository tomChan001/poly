# 审核草稿防刷新覆盖设计

## 背景

审核页面每五秒重新加载一次市场对。当前实现会在每次加载后用服务端返回的
`checklist` 和 `notes` 重置本地表单，导致审核员尚未勾完规则核对项时，输入就被
下一次自动刷新清空，`确认 EXACT` 按钮也无法稳定启用。

## 目标

- 保留每五秒一次的候选列表刷新。
- 当前候选的勾选或备注一旦被用户修改，自动刷新不得覆盖这些未提交内容。
- 切换候选时不弹出提醒，直接丢弃原候选的未提交内容，并加载新候选的服务端值。
- 审核保存成功后，表单与服务端返回的已保存结果保持一致。

## 方案

在 `PairSettingsPage` 中显式记录当前表单是否为未提交草稿。

1. 首次选中候选时，从候选的 `checklist` 和 `notes` 初始化表单，草稿状态为干净。
2. 用户修改任意勾选项或备注后，将草稿标记为脏。
3. 定时刷新仍替换候选列表和候选状态，但候选 ID 未变化且草稿为脏时，不重新初始化
   当前表单。
4. 用户切换候选时，无条件从新候选初始化表单并清除脏状态，不显示确认提示。
5. 审核保存成功后，用接口返回值更新候选列表和当前表单，并清除脏状态。

该方案只隔离“后台数据刷新”和“当前表单草稿”两个状态，不暂停候选发现，也不增加
跨候选草稿缓存。

## 异常与并发

- 自动刷新失败时保留现有草稿，并继续显示读取错误。
- 保存失败时保留用户草稿，允许修正或重试。
- 当前候选在刷新后消失时，按现有选择规则切换到列表中的首个候选；原草稿直接丢弃。
- 当前候选的服务端状态在编辑期间变化时，列表状态可以更新，但不覆盖本地草稿；最终
  保存仍以服务端接口校验结果为准。

## 测试

增加前端回归测试覆盖：

1. 选中候选并修改部分勾选和备注。
2. 推进定时器超过五秒，让 `/api/pairs` 再次返回原服务端值。
3. 断言本地勾选和备注仍然保留。
4. 勾完全部项目并提交，断言 `确认 EXACT` 可用且请求包含完整草稿。
5. 切换候选时，断言旧草稿被丢弃，新候选加载自己的服务端值且没有提醒。
