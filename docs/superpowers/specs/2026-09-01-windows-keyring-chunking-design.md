# Windows 凭证库长私钥分片设计

## 背景与目标

Windows Credential Manager 通过当前 `keyring` 后端写入字符串时，短凭证可正常往返，但标准 2048 位 RSA PKCS#8 PEM（约 1700 字符）会触发 `CredWrite 1783`。目标是在不改变集成 API 和操作界面的前提下，让 Kalshi RSA 私钥安全保存、读取、替换和删除，并避免把凭证或底层异常暴露给客户端。

## 存储格式

`KeyringSecretStore` 保持现有短凭证格式。长度不超过安全阈值的值仍直接写在原有键名下，确保 Oddpool Token、Polymarket Secret 和既有数据无需迁移。

超过阈值的值拆成多个不超过 900 字符的分片。每次写入使用内容 SHA-256 摘要生成独立分片命名空间：

- 主键：只保存原样短凭证；长凭证不占用主键，避免任何短值与内部清单内容碰撞；
- 清单 sidecar 键：保存固定前缀、格式版本、类型标记、分片数量和完整内容摘要；
- 分片键：包含原键名、内容摘要和从零开始的分片编号；
- 分片值：只包含该段凭证文本。

先写全部新分片，最后写清单 sidecar。读取时优先检查 sidecar；没有 sidecar 才读取原样主键。这样写入中途失败时旧值仍然有效，清单生效后再清理旧主键或旧分片，并且即使短值文本恰好长得像合法清单也能原样往返。

## 读取、替换与删除

读取时先检查独立清单 sidecar；不存在时直接返回主键中的普通字符串。识别到合法版本化清单后，按顺序读取分片、拼接并校验 SHA-256。缺少分片、清单损坏或摘要不匹配都视为凭证存储损坏，不返回部分内容。

替换时支持短值、长值之间双向切换。新值成功提交后清理旧主键或旧版本分片。删除长值时先解析清单，清理可能残留的主键，再删除 sidecar 以停用活动引用，最后有限重试清理全部分片；这样即使分片清理失败，也不会留下仍然生效但已缺片的损坏凭证。不存在的键保持幂等。

## 错误处理与安全

底层 `keyring` 异常统一转换为不包含键值、私钥、Key ID 或底层凭证内容的存储异常。集成保存接口返回可操作的安全错误，而不是未处理的 HTTP 500。日志与响应不得包含 PEM、分片内容或完整底层错误参数。

分片仍全部存储在同一个 Windows Credential Manager 服务命名空间中，不写明文文件、不读取用户选择的 TXT 路径，也不改变只写密码框行为。

## 测试与验收

使用可配置单条长度上限的假 keyring 后端复现 Windows 行为，并覆盖：

1. 约 1700 字符的多行 PEM 可完整往返；
2. 短凭证保持单条、兼容既有格式；
3. 长值替换为短值和长值替换为另一长值时不遗留旧分片；
4. 删除长值会删除清单和全部分片；
5. 缺失分片或摘要不匹配时失败关闭；
6. 底层写入失败不会提交新清单，API 返回脱敏错误；
7. 在真实 Windows Credential Manager 上用生成的测试 RSA 私钥完成写入、读取和删除，不接触用户实际私钥。

完成后运行后端全量测试、Ruff、前端回归构建，并通过本机保存接口验证不会再出现模糊 500。
