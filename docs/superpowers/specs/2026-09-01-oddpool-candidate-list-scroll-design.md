# Oddpool 候选列表视口内滚动设计

## 背景

审核页面左侧的 Oddpool 候选当前直接渲染在 `.pair-list` 中。候选数量增加时，列表会
持续撑高 `.pair-workspace` 和整个页面，用户需要滚动很长的页面才能在候选之间切换，
也会让右侧审核详情失去稳定的视觉位置。

## 目标

- 仅左侧 Oddpool 候选列表独立纵向滚动。
- 列表区域不超过当前视口可用高度。
- 左侧“Oddpool 候选”标题和数量保持可见，不随候选内容滚走。
- 右侧审核详情继续按现有页面流正常展开，不新增内部滚动。
- 不改变候选加载、定时刷新、选中状态或审核提交逻辑。

## 设计

在 `.pair-list` 的固定 header 下新增 `.pair-list-scroll` 内容容器。空状态和所有
`.pair-row` 都放入该容器中。

桌面和平板宽度下，滚动容器使用视口单位扣除顶部导航、交易模式条、运行状态条、
页面标题和上下间距后的高度，并设置合理上限。候选较少时容器自然收缩；候选内容
超过上限时显示纵向滚动条。

滚动容器设置：

- `overflow-y: auto`，只允许候选内容纵向滚动；
- `overscroll-behavior: contain`，到达列表边界时不把滚动继续传给整个页面；
- `scrollbar-gutter: stable`，滚动条出现时不挤压候选文本；
- `min-height: 0`，允许其在 grid/flex 布局中正确收缩。

移动端审核工作区会改为单列。候选滚动容器使用更小的视口比例和像素上限，保证
用户仍能在列表下方看到并进入审核详情；左侧与右侧现有的上下边框关系保持不变。

## 可访问性与交互

- 保留 `section[aria-label="自动候选列表"]`。
- 滚动容器增加明确的可访问名称，使键盘和辅助技术能够识别这是 Oddpool 候选内容。
- 候选按钮、选中样式、状态标签和点击行为完全保持现状。
- 不强制滚动位置随 5 秒自动刷新重置；React 继续复用稳定 key，现有滚动位置应保持。

## 测试与验收

1. 组件测试确认固定 header 与候选滚动容器分离，候选和空状态位于滚动容器内。
2. 现有审核选择、规则核对和保存测试继续通过。
3. 桌面尺寸下使用大量候选验证：左侧列表出现纵向滚动条，列表底部不超过视口，
   header 始终可见，右侧审核详情未增加内部滚动。
4. 手机尺寸下验证单列布局：候选列表高度受限并可滚动，审核详情位于其下方。
5. 前端测试、构建和 lint 通过。

## 非目标

- 不增加候选搜索、筛选、分页或虚拟列表。
- 不固定或吸附整个左侧列表。
- 不改变右侧审核详情的高度和滚动行为。
