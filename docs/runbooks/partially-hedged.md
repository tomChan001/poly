# 部分对冲处置

## 触发条件

任一双腿执行的两端去重后成交数量不一致时，执行状态必须立即进入
`PARTIALLY_HEDGED`，数据库开仓总开关必须关闭。不得等待下一轮行情后继续开新仓。

## 自动动作

1. 按平台 fill ID 去重，取两端较小成交量作为已配对数量。
2. 对数量缺口重新读取缺失腿的原生订单簿，计算一次 FOK 补对冲的最坏损失。
3. 最坏损失不超过当前风险策略的 `maximum_unhedged_loss` 时，只发送一次绑定原执行
   correlation ID 的补对冲订单。
4. 补对冲超过损失上限时，在已成交端按预设限价发送一次平仓 FOK。
5. 任何超时都按稳定 client order ID 查询，不得直接重下。

## 人工审核

人工只处理异常证据和系统恢复，不逐笔批准订单。操作者必须核对两端开放订单、成交、余额、
费用及本地账本；只有全量对账一致且事故原因已记录后，才可按 kill switch runbook 恢复开仓。

超过 `maximum_unhedged_seconds`、自动动作未完整成交或实际损失超过上限时，将执行标记为
`EXCEPTION` 并发送最高优先级告警。不得仅因告警已送达而重新开仓。
